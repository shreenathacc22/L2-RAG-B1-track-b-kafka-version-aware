Version-aware RAG: old runbooks never reach the answer

Old and current Kafka runbooks read almost identically, so similarity search keeps serving outdated thresholds, ports and on-call teams. One metadata filter, where={"superseded": False}, removes them before ranking.

0/9 → 9/9version-conflict cases passed
7/7 → 7/7exact-value cases (unchanged)
+0.9 mslatency cost of the filter

How it works

Every stage existed in the class lab except the version filter. The metadata comes from a separate manifest.json, so the embedded text is exactly what a reader sees.

16 runbooks→load→+ version metadata→chunk→embed (MiniLM)→Chroma
question→embed→VERSION FILTER→top-4 by similarity→LLM answer (Python version only)

On this page, the stored chunk vectors come from the Python pipeline, and questions are embedded in your browser with transformers.js (fp32). Checked before publishing: for all 21 test questions, filter OFF and ON, the browser returns the same top 4 in the same order as the Python system (42/42).
